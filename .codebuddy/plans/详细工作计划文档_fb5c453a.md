## 用户需求
为"轻量无人机"项目产出一份**非常详细的工作计划**，形态为「全流程大框架 + 小点」：以全流程阶段为大框架，每个阶段下拆解为具体工作项。

## 交付内容
- 新建独立文档 `docs/WORKPLAN.md`，与现有 `docs/DESIGN_FLOW.md` 分工互补、不重复（后者讲设计路径与理由，本计划讲推进事项与验收）
- 覆盖 P0 至 P8 全流程：P0 范围/BOM → P1 硬件 → P2 软件环境 → P3 驱动 → P4 算法 → P5 任务编排 → P6 调试调参 → P7 首飞 → P8 扩展（定高/磁力计/遥控/定点）
- 前期阶段（P0–P7）详细，扩展阶段（P8）适度详细

## 核心要求
- 粒度到"工作项/交付物"级（示例：原理图设计、PCB 设计、校验），不写操作步骤级细节
- 每项要素：编号、工作内容、产出物、验收标准（可勾选）、前置依赖、分工
- 含进度看板（反映 P0 已完成、P1 部分完成、P2–P8 未开始的真实进度）、横向专题（采购时点/安全红线/风险与对策/遗留待修正）与下一步 TOP 3
- 效果：结构清晰、逐条可勾选推进、与现有文档体系衔接一致

## 文档结构规范（WORKPLAN.md）
1. 顶部：标题 + 一句话总目标
2. 进度看板：P0–P8 状态表（已完成 / 部分完成 / 未开始）
3. 工作项规范：编号规则（P1-1、P1-2…）、要素定义、依赖与可并行标注约定
4. 逐阶段工作项（P0–P8）：每阶段一张表，列 = 编号｜工作内容｜产出物｜验收标准（勾选项）｜前置依赖｜分工
5. 横向专题：采购与下单时点清单、安全红线、风险与对策、遗留待修正
6. 收尾：下一步 TOP 3

## 内容红线与事实来源
- 粒度红线：工作项级；禁止函数名、命令行、软件点击步骤；禁止工期天数估算
- 事实来源：`docs/ARCHITECTURE.md`、`docs/DESIGN_FLOW.md`、`docs/BOM.md`、`hardware/` 现状（板框 v8 完成）
- 必须遵守已确认决策：方案 B 无刷（1104×4 + 4合1 ESC + 2S）、F411CEU6 核心板、MPU6050 居中减震、蓝牙 HC-05（USART2）控制链路、failsafe（无有效指令超过 500ms 自动收油）与物理急停与解锁逻辑、板即机架打样 5 片、预算约 193 元（含充电器约 211 元）
- 安全红线独立成节：无桨与系绳测试、解锁逻辑、failsafe、物理急停
- 遗留待修正仅记录、不在本任务修复：§9.2 仍写 IBUS 预留（应为蓝牙）、电池仍写 1S/2S（应为 2S）
- 与 DESIGN_FLOW.md 分工：不重复算法理由与设计决策；依赖关系须真实（原理图→PCB→校验→打样→焊接→装配；软件链可与硬件链并行并显式标注）
