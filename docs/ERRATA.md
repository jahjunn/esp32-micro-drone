### 0.1 状态图例

### 0.2 「修好了」的判定标准（三条全满足才算 ✅）

1. **代码改对了** —— 不是绕过去，也不是改测试迁就代码；
2. **有断言兜底** —— 至少一条 `CHECK()` 会在旧代码上失败、在新代码上通过；
3. **在干净环境跑过** —— 删掉编译产物重新编译，全绿，且失败时退出码非 0。

> 只满足第 1 条的，状态一律记 🟨，不算完成。这条规则就是防「假绿灯」。

| 级别 | 含义 |

| **P1** | 首飞前必须解决，否则现场必然踩坑 |
| **P2** | 首飞后优化，不影响安全性 |

### E-02　倾角 >60° 立即切电　P0
- **根因**：瞬时阵风吹过 `60°` 与真倒扣（`>110°`）或持续失控未区分，第 1 拍直接切电导致本可自稳救回的姿态直接坠机。
- **修法**：基于三维投影 `cos_tilt = cosf(roll) * cosf(pitch)`（消除仰角万向锁盲区并防 NaN）做分级保护——`>110°`（倒扣）及地面怠速（`≤5%`）翻倒单拍立即 `FAILSAFE`；飞行中（`>5%`）处于 `>60°` 时归零摇杆目标并将油门上限压至 `45%`（保留 `LOWBAT_LAND` 25% 上限覆盖；悬停推力及恢复性能尚未标定），滞回退出角设 `45°` 防撞墙反弹清零计时，连续 `0.8s`（320 拍）未回到 `≤45°` 则判定失控切入 `FAILSAFE`。
- **进度**：✅ 代码与 `test_safety.c`（含 `9a~9f` 与 `5c`）已于本机清理重编（`test_safety.exe`）并全绿通过，待最终复核归档。

#### F-01　控制任务无心跳监控，卡死即定速飞走　P1
- **位置**：`main.cpp:65-152`（`vControlTask`）、`main.cpp:155+`（`vCommTask`）
- **现象**：`vControlTask` 一旦停摆（栈溢出、`Wire` 死锁、内存踩踏），`motor_out_write()` 不再被调用，LEDC 保持最后一次占空比 —— 20 kHz PWM 持续驱动四路电机，飞机会以固定推力飞走。`main.cpp:131-136` 的总闸门是**逻辑层**判断，任务不跑就永远执行不到；`platformio.ini` 也未把该任务挂到 `esp_task_wdt`。
- **修法**：
  1. 新建 `firmware/src/flight/heartbeat.h`（纯 C、无 Arduino 依赖，可桌面单测）：
     ```c
     #pragma once
     #include <stdint.h>
     #include <stdbool.h>

     // 心跳超时判定：now / last 均为 millis() 毫秒计数，uint32 差值天然回绕安全
     static inline bool heartbeat_stale(uint32_t last_seen_ms, uint32_t now_ms, uint32_t timeout_ms) {
         return (uint32_t)(now_ms - last_seen_ms) > timeout_ms;
     }
     ```
  2. `config.h` 增加 `#define CTRL_HEARTBEAT_TIMEOUT_MS 200U`（= 80 个控制周期）。
  3. `main.cpp` 增加 `static volatile uint32_t s_ctrl_heartbeat_ms = 0U;`；在控制任务**每拍末尾**（`portEXIT_CRITICAL(&s_telem_mux);` 之后）写 `s_ctrl_heartbeat_ms = (uint32_t)millis();`；`!s_imu_boot_ok` 的提前 `continue` 分支（`main.cpp:89-100`）里也要写一次，避免上电未接 MPU 时误触发。
  4. `vCommTask` 每轮 20 Hz 开头：
     ```c
     if (heartbeat_stale(s_ctrl_heartbeat_ms, (uint32_t)millis(), CTRL_HEARTBEAT_TIMEOUT_MS)) {
         motor_out_stop_all();   // 控制拍停摆 → 强制断桨
     }
     ```
- **验收**：新增 `firmware/test/test_heartbeat.c`，四条断言：`(1000,1100,200)==false`、`(1000,1300,200)==true`、回绕 `(0xFFFFFF00u,0x00000100u,200)==true`、`(0xFFFFFF00u,0xFFFFFF10u,200)==false`；并把 `heartbeat` 追加进 §5 测试数组。

#### F-02　NaN 帧把「假水平」灌进 Mahony，40 拍可拉偏 5.7°　P1
- **位置**：`controller.h:231-236`（NaN 替换）、`controller.h:272-275`（Mahony 调用）、`main.cpp:105-121`（I2C 失败传 NAN）
- **现象**：`mpu6050_read()` 失败时传入全 NAN，`controller.h:233` 用 `{0,0,1}` 顶替加速度并**照常**调用 `mahony_update_imu()`。Mahony 的误差项 `e = a × v` 会把这帧假水平当成真实量测：机身实际倾 30° 时 `|e| ≈ 0.5`，kp = 2.0 下每拍拉 0.14°，连续 40 拍（100 ms）累计 **≈ 4~5.7°**（经 40 Hz 加计 LPF 后约 4°），再以 τ ≈ 0.5 s 缓慢回正。这把「NaN 防火墙」的意图用反了——防火墙应只保证滤波器不中毒，而不是伪造一个姿态量测。
- **修法**：
  1. `mahony.h` 增加「只积分、不修正」入口（**复用**现有四元数积分段，抽成内部函数，勿复制粘贴）：
     ```c
     static inline void mahony_update_gyro_only(Mahony_t *m, Vector3_t gyro, float dt) {
         Vector3_t g = { gyro.x - m->ix, gyro.y - m->iy, gyro.z - m->iz };  // 已学零偏仍要持续补偿
         mahony_quat_integrate(m, g, dt);                                    // 抽出现有积分段
         mahony_normalize(m);
     }
     ```
  2. `controller.h`：在 `controller.h:232` 之前求 `bool sample_valid = controller_vec3_is_finite(raw_gyro_frd) && controller_vec3_is_finite(raw_accel_frd);`；NaN 分支仍把 `raw_gyro_frd = fc->gyro_bias`（保证 LPF 与校准器不吃 NAN），但把 `controller.h:275` 改为：
     ```c
     if (sample_valid) {
         mahony_update_imu(&fc->ahrs, gyro_filt, accel_filt, dt);
     } else {
         mahony_update_gyro_only(&fc->ahrs, gyro_filt, dt);
     }
     mahony_to_euler(&fc->ahrs, &fc->attitude);
     ```
  3. 加计 LPF 仍每拍喂 `accel_filt`（保持滤波器连续），只是该拍不参与修正。
- **验收**：`test_controller.c` 新增断言——先喂 300 拍倾斜数据（例如 `accel = {0.0f, 0.5f, 0.866f}`，约 30° 倾角）让姿态收敛并记录 `roll_before`；再注入 40 拍全 NAN 帧；断言 `fabsf(fc.attitude.roll - roll_before) < 1.0°`。**用变化量而不是绝对角**，避免符号/轴争议。旧代码在这 40 拍里会变化 4° 以上，断言必失败。

#### F-03　BLE 断连回调里直接重开广播　P1
- **位置**：`ble_server.cpp:44-54`（`onDisconnect` 内 `ble_server.cpp:53`）
- **现象**：Bluedroid 的 GATT 回调运行在协议栈任务上下文，此处直接调 `BLEDevice::startAdvertising()` 有概率返回 `ESP_ERR_NO_MEM` 或阻塞协议栈，表现为**断连后再也搜不到设备、必须复位**。控制环在 Core1 不受影响，属可用性问题而非安全问题。
- **修法**：新增 `static volatile bool s_need_readvertise = false;`，`onDisconnect` 只置位；新增 `void ble_comm_poll(void)`（`ble_server.h` + `ble_server.cpp`）：
  ```c
  void ble_comm_poll(void) {
      if (s_need_readvertise) {
          s_need_readvertise = false;
          BLEDevice::startAdvertising();
      }
  }
  ```
  `vCommTask` 中每 50 ms 调用一次 `ble_comm_poll();`（可用 `tick % 2` 分频，20 Hz→10 Hz 略慢无妨，建议直接 20 Hz 调用）。
- **验收**：`pio run` 编译通过 + 实机：手机主动断开后 3 s 内能重新扫到 `UAV-ESP32S3`，连续断连 10 次无卡死。

#### F-04　`millis()` 竞态导致假失联　P2
- **位置**：`ble_server.cpp:127-146`（`now_ms` 在锁外读取）、`ble_server.cpp:69-74`（写入端同理）
- **现象**：写端在临界区内写 `s_last_rx_ms = now_ms`（该 `now_ms` 读于进锁之前），读端也在锁外读 `now_ms` 再进锁。极窄窗口下 `last_ms > now_ms`，`(uint32_t)(now_ms - last_ms)` 下溢成 ≈ 4.29e9 ms → 单拍判成失联 → **锁存 FAILSAFE（需拨杆才解除）**。按 50 Hz 写、约 200 ns 窗口估算，概率约 1e-5 / 秒。
- **修法**：
  1. `ble_comm_get_command()` 把 `uint32_t now_ms = millis();` 移到 `portENTER_CRITICAL` **之后**；
  2. 计算年龄时加防御：`uint32_t age = (now_ms >= last_ms) ? (now_ms - last_ms) : 0U;`
  3. `onWrite()` 同样把 `millis()` 挪进临界区。
- **验收**：代码审查（窗口无法稳定复现）；在代码注释中写明「必须在锁内取时，否则会下溢为 4.29e9 假失联」。

#### F-05　内环积分权限仅 4%，配不平重心偏心　P2
- **位置**：`controller.h:127-129`（`integral_limit = 0.20`、`ki = 0.08`）
- **量化**：`i_term` 上限 = 0.08 × 0.20 = **0.016**，占内环输出上限 0.40 的 4%。按 45 g 整机、21 mm 力臂估算，2 mm 电池偏心需 ≈ 0.07 的归一化力矩配平 —— **超出积分能力 4 倍**，表现为「总往一边飘、打杆修正后松杆又飘回去」的恒定 2~3° 倾角，而不是发散。
- **修法**：`pid_init(&fc->rate_roll_pid, 0.25f, 0.08f, 0.004f, 1.20f, 0.40f);` 与 `rate_pitch` 同步（`i_term` 上限 0.096 ≈ 24%）；`rate_yaw` 保持 `0.20f` 不动。
- **验收**：`test_pid.c` 新增：`ki = 0.08, int_limit = 1.2`，setpoint = 0、measured 恒 0.2（等效 0.2 rad/s 稳态偏差，dt 取 0.0025）跑 **1200 拍（3 s）**，断言 **`fabsf(pid.integral * pid.ki) >= 0.04`**（误差为负、积分为负，务必取绝对值；旧参数最多到 0.016，断言必失败）。

#### F-06　5% 油门门槛处推力≈0、差动权限满格　P2
- **位置**：`controller.h:335-341`
- **现象**：`throttle = 0.051` 时 `mix_throttle ≈ 0.001`，但三轴力矩仍可达 ±0.40，经 `mixer_apply_idle` 映射后四路落在 **12%~47%**。地面推杆略过 5% 时电机会剧烈抽动甚至侧倾；空中低油门段则是「没有推力却有满舵权限」。
- **修法**：增加随油门渐入的权限系数：
  ```c
  #define CTRL_AUTH_FULL_THROTTLE 0.15f   // 15% 油门以上给满力矩权限
  float auth = clampf((cmd.throttle - SAFETY_ARM_MAX_THROTTLE) /
                      (CTRL_AUTH_FULL_THROTTLE - SAFETY_ARM_MAX_THROTTLE), 0.0f, 1.0f);
  mixer_quad_x(mix_throttle, roll_torque * auth, pitch_torque * auth, yaw_torque * auth, out_motors);
  ```
  15% 油门对应 `mix_throttle ≈ 0.105`（`apply_idle` 后 0.21），此时满权限差动 0.21 ± 0.35 仍在安全区。
- **验收**：`test_controller.c` 新增：`throttle = 0.051`、`roll_target = 25°`、初始姿态 0°，跑 1 拍后断言 `(max(m1..m4) - min(m1..m4)) < 0.06`（旧代码 ≈ 0.70，必失败）。

#### 本轮观察项（**不列入本轮修复**，避免与已验证行为冲突）
- **vbat ADC 400 Hz 采样**（`main.cpp:86`）：每 2.5 ms 调一次 `analogReadMilliVolts()`，约占 4~8% CPU。可改为 8 拍分频（50 Hz）并把 `CTRL_VBAT_LPF_ALPHA` 由 0.02 提到 0.16（时间常数同为 0.125 s）。**改动的安全性需台架复核，暂缓。**
- **地面怠速分支绕过总闸门**（`controller.h:292-301` 在 `safety_apply_motor_gate` 之前 `return`）：低压锁存态下 12% 怠速不受 25% 缓降门限约束，影响极小。
- **C-02（动态混控余量）**：仍为 ⬜，属 P2 优化，不阻塞首飞。

## 8. 错题反思与工程实战经验总结（Lessons Learned）

> **导语**：每一次踩坑，都是物理规律对工程傲慢的严厉修正。以下提炼自本项目在全栈重构、审查与移动端实飞调试过程中的五大核心实战经验，作为团队后续软硬件开发、上板调参和版本迭代的避坑指南。

### 8.1 坐标系与符号链必须建立“端到端全链路契约”
- **原生传感器坐标不等于飞控坐标**：正面朝上贴装的 MPU6050 芯片物理原生输出为 **FLU（前左上）** 系，静止时测得的垂直支撑比力为 $+1g$。飞控算法统一以 **FRD（前右下）右手系**为唯一物理基准。**严禁直接把驱动层的原始读数裸传给姿态解算**，必须经过 `controller_map_flu_to_frd()` 转换（角速度映射为 `{gx,-gy,-gz}`；加计比力先旋转至 FRD，再额外取反得到 Mahony 的重力观测 `{-ax,+ay,+az}`，故输出 z 保持正号），否则加计与重力向量反相，滤波一开机即向倒扣发散。
- **人机操控习惯与动力学姿态的转换边界**：地面站或遥控手柄的航模美国手（Mode-2）习惯是“右摇杆前推向前方加速”，但这在飞行力学中对应的是**低头前飞（FRD 负俯仰，$-Pitch$）**。若遥控链路不假思索地把前推直传为 $+1000$，飞机起飞推杆就会瞬间仰头倒扣。输入合成层（`buildControlInput`）必须在最前端清晰划分职责边界，确保“操作直觉”与“物理定律”各司其职。
- **混控器必须推导力矩差动符号**：不能凭感觉写混控矩阵。必须紧扣物理力矩：Roll 右滚（$+Roll$）要求左侧电机（M3/M4）增速、右侧电机（M1/M2）减速；Pitch 抬头（$+Pitch$）要求前侧电机（M1/M4）增速、后侧电机（M2/M3）减速；Yaw 顺时针（$+Yaw$）要求逆时针桨（M1/M3, CCW）增速、顺时针桨（M2/M4, CW）减速。

---

### 8.2 移动端 Web 地面站的“人机交互与防死锁设计”
- **自遮挡浮层死锁陷阱**：在小屏手机上使用原生 CSS 浮动卡片或 `<details>` 标签展开高级设置时，浮动面板极易在高度超出视口时遮挡触发展开的 `<summary>` 按钮自身，导致“进得去出不来”。**正解是使用现代浏览器原生 `<dialog>` 元素**，配合全屏遮罩点击退出、ESC 键监听和显式关闭按钮，杜绝页面卡死。
- **相对位移触控（Relative Drag）与零阶跃防暴冲**：手机玻璃没有实体航模控的物理弹簧与阻尼。手指落下的瞬间，绝不能直接按触控点的绝对坐标计算油门，否则在悬停或低油门时手指重新触碰屏幕就会引发推力瞬间从 10% 跳变到 60% 导致暴冲炸机。**必须采用“落指处即原点”的相对位移机制**：按下时只记录锚点、拖拽时才累加位移，手指抬起重新按下时必须稳固锁存当前已有油门。
- **CSS `translate(%)` 相对位移陷阱**：在纯 CSS/JS 渲染摇杆滑块时，`transform: translate(x%, y%)` 中的百分比是**相对于滑块（Knob）自身尺寸**，而非外层底盘轨道直径。若滑块直径为轨道的 26%，位移就必须换算为 $135\%$ 左右，否则滑块只会在底盘中心微弱蠕动，造成手感严重粘滞。
- **界面极简主义才是最高安全性**：室外阳光下飞手心理极度紧张，繁复的舵量切换、双向微调在移动端不但没有实用价值，反而极易导致误触。将复杂配置沉淀到弹窗中，在未连接实体手柄时自动隐藏手柄油门切换，能最大限度降低人因失误。

---

### 8.3 安全状态机的“单向锁存”与“分级自稳”哲学
- **低压反弹陷阱与单向锁存（Sticky）**：1S 锂电池内阻较大，大油门机动时电池端电压被大电流压降拉低；一旦飞控收油门试图降落，放电电流骤降导致电压立即回弹到 3.5V 以上。若安全逻辑只写瞬态 `if (vbat < 3.3V)`，飞机会在空中陷入“低压降油门 → 电压回弹恢复大油门 → 再次低压”的往复振荡抽搐（发羊癫疯）。**正解是低压迫降（`LOWBAT_LAND`）必须设计为单向锁存状态**，一经触发，除非飞手主动拨动摇杆上锁归零，否则绝不自动退回正常飞行态；同时送入安全状态机的模拟量必须经过数字低通滤波（`vbat_filtered`），消除 20kHz 电机 PWM 开关毛刺。
- **瞬时阵风倾角与真倒扣的分级救机（E-02）**：单纯写 `tilt > 60° 立即断电` 是机械教条主义——户外一阵强侧风吹过，飞机倾角瞬时达到 62° 但机身姿态完全受控，此时直接切断电机只会让原本能自稳救回的飞机直接自由落体坠毁。**正解是分级保护**：
  - `>110°`（真倒扣）：单拍立即 `FAILSAFE` 断电停机，防止倒地后桨叶刮地烧毁 MOS 管或伤人；
  - `>60°`（大角度失稳）：摇杆指令强制归零，油门上限设为45%，归零姿态目标请求回平；实际差动还受混控饱和限制，恢复能力待测；设置 45° 滞回退出角与 0.8 秒（320 拍）失控保护计时，超时无法自救才执行切电。
- **失联与切后台的绝对安全底线（E-04）**：手机切后台、来电弹窗、微信消息下拉、手柄蓝牙意外断连，若系统仅回中弹簧轴而不强制归零油门，如果飞机此前正处于 60% 油门推力，飞机将直接定速飞丢。**必须实施组合保护**：强制 `armed = false` + 油门归零 + 连发 3 帧急停帧，任何输入链路异常一律进入最高安全待命态。

---

### 8.4 测试哲学：向“假绿灯”和“凑参数过关”宣战
- **杜绝 Fake Green Tests**：没有任何断言、只在末尾 `printf("PASS\n")` 并无条件 `return 0` 的测试是工程自欺欺人。所有的测试用例必须内置带非零退出的 `CHECK(cond, msg)` 断言，并在编译阶段开启 `-Wall -Wextra -Werror=return-type`。当测试出现超调、发散或偏差时，**严禁通过盲目修改阈值或迁就测试数据来强行刷绿**，必须追查滤波器冷启动、积分累加边界与时序分频的真实根因。
- **桌面单测与交叉编译完全解耦**：核心算法头文件（LPF、Mahony、PID、混控、安全状态机）必须保持高移植性的纯 C 语言编写（无任何单片机专有库依赖）。这样在没有物理单片机硬件或交叉编译工具链尚未下完的情况下，也能在 PC 宿主机上 50 毫秒内完成全逻辑自动化验收，极大解放了敏捷迭代效率。

---

### 8.5 交叉编译环境与工程资产管理
- **本地庞大工具链与版本库严格隔离**：PlatformIO 下载的交叉编译器和官方 SDK（通常几百 MB）属于本地机器运行环境，必须放入 `.gitignore`。代码仓库只应当保留轻量纯净的配置文件（如锁定版本号 `espressif32@6.9.0` 的 `platformio.ini`）与业务源代码。
- **开发节奏不被环境安装卡脖子**：由于算法和协议已经在桌面测试矩阵中取得了真绿灯闭环，开发者完全可以先推进代码归档、文档撰写与物料采购，工具链下载完全可以后台异步进行，保持高效稳健的开发心流。
