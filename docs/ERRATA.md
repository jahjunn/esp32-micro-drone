### 0.2 「修好了」的判定标准（三条全满足才算 ✅）

1. **代码改对了** —— 不是绕过去，也不是改测试迁就代码；
2. **有断言兜底** —— 至少一条 `CHECK()` 会在旧代码上失败、在新代码上通过；
3. **在干净环境跑过** —— 删掉编译产物重新编译，全绿，且失败时退出码非 0。

> 只满足第 1 条的，状态一律记 🟨，不算完成。这条规则就是防「假绿灯」。

## 3. 待修详情

### E-01　偏航杆完全不生效　P0
- **根因**：`controller.h` 外环计算后遗漏 `fc->desired_rate.z = cmd.yaw_rate_target;`，导致 `desired_rate.z` 恒为 `0`。
- **修法**：恢复 `fc->desired_rate.z = cmd.yaw_rate_target;`，并在 `test_controller.c` 补齐四通道（Throttle / Roll / Pitch / Yaw）端到端差动断言。
- **进度**：✅ 已改并编译运行全绿（`test_controller.exe` 断言 `5a/5b` 通过）。

### E-02　倾角 >60° 立即切电　P0
- **根因**：瞬时阵风吹过 `60°` 与真倒扣（`>110°`）或持续失控未区分，第 1 拍直接切电导致本可自稳救回的姿态直接坠机。
- **修法**：基于三维投影 `cos_tilt = cosf(roll) * cosf(pitch)`（消除仰角万向锁盲区并防 NaN）做分级保护——`>110°`（倒扣）及地面怠速（`≤5%`）翻倒单拍立即 `FAILSAFE`；飞行中（`>5%`）处于 `>60°` 时归零摇杆目标并将油门上限压至 `45%`（`mix=0.40` 匹配内环满额纠偏力矩且≈悬停推力，显著减少低空掉高，保留 `LOWBAT_LAND` 25% 覆盖锁存），滞回退出角设 `45°` 防撞墙反弹清零计时，连续 `0.8s`（320 拍）未回到 `≤45°` 则判定失控切入 `FAILSAFE`。
- **进度**：✅ 代码与 `test_safety.c`（含 `9a~9f` 与 `5c`）已于本机清理重编（`test_safety.exe`）并全绿通过，待最终复核归档。

### E-03　陀螺仪校准容差与状态提示　P1
- **根因**：`0.15 rad/s` 峰峰值在桌面风扇微振下易反复清零，且未向遥测暴露“正在校准”状态（注：**严禁在手晃未校准通过时超时强行解锁起飞**，必须保证安全底线）。
- **修法**：将静止峰峰值容差调整至合理桌面阈值（`0.25 rad/s`），并在安全/遥测状态或校准标志中提供明确可观测性。

### E-04　手柄断连 / 切后台不上锁 + 前端 FRD/仿真器对齐　P1

## 8. 错题反思与工程实战经验总结（Lessons Learned）

> **导语**：每一次踩坑，都是物理规律对工程傲慢的严厉修正。以下提炼自本项目在全栈重构、审查与移动端实飞调试过程中的五大核心实战经验，作为团队后续软硬件开发、上板调参和版本迭代的避坑指南。

### 8.1 坐标系与符号链必须建立“端到端全链路契约”
- **原生传感器坐标不等于飞控坐标**：正面朝上贴装的 MPU6050 芯片物理原生输出为 **FLU（前左上）** 系，静止时测得的垂直支撑比力为 $+1g$。飞控算法统一以 **FRD（前右下）右手系**为唯一物理基准。**严禁直接把驱动层的原始读数裸传给姿态解算**，必须经过 `controller_map_flu_to_frd()` 转换（$a_{frd}.z = -a_{flu}.z$），否则加计与重力向量反相，滤波一开机即向倒扣发散。
- **人机操控习惯与动力学姿态的转换边界**：地面站或遥控手柄的航模美国手（Mode-2）习惯是“右摇杆前推向前方加速”，但这在飞行力学中对应的是**低头前飞（FRD 负俯仰，$-Pitch$）**。若遥控链路不假思索地把前推直传为 $+1000$，飞机起飞推杆就会瞬间仰头倒扣。输入合成层（`buildControlInput`）必须在最前端清晰划分职责边界，确保“操作直觉”与“物理定律”各司其职。
- **混控器必须推导力矩差动符号**：不能凭感觉写混控矩阵。必须紧扣物理力矩：Roll 右滚（$+Roll$）要求左侧电机（M3/M4）增速、右侧电机（M1/M2）减速；Pitch 抬头（$+Pitch$）要求前侧电机（M1/M4）增速、后侧电机（M2/M3）减速；Yaw 顺时针（$+Yaw$）要求逆时针桨（M1/M3, CCW）增速、顺时针桨（M2/M4, CW）减速。

### 8.2 移动端 Web 地面站的“人机交互与防死锁设计”
- **自遮挡浮层死锁陷阱**：在小屏手机上使用原生 CSS 浮动卡片或 `<details>` 标签展开高级设置时，浮动面板极易在高度超出视口时遮挡触发展开的 `<summary>` 按钮自身，导致“进得去出不来”。**正解是使用现代浏览器原生 `<dialog>` 元素**，配合全屏遮罩点击退出、ESC 键监听和显式关闭按钮，杜绝页面卡死。
- **相对位移触控（Relative Drag）与零阶跃防暴冲**：手机玻璃没有实体航模控的物理弹簧与阻尼。手指落下的瞬间，绝不能直接按触控点的绝对坐标计算油门，否则在悬停或低油门时手指重新触碰屏幕就会引发推力瞬间从 10% 跳变到 60% 导致暴冲炸机。**必须采用“落指处即原点”的相对位移机制**：按下时只记录锚点、拖拽时才累加位移，手指抬起重新按下时必须稳固锁存当前已有油门。
- **CSS `translate(%)` 相对位移陷阱**：在纯 CSS/JS 渲染摇杆滑块时，`transform: translate(x%, y%)` 中的百分比是**相对于滑块（Knob）自身尺寸**，而非外层底盘轨道直径。若滑块直径为轨道的 26%，位移就必须换算为 $135\%$ 左右，否则滑块只会在底盘中心微弱蠕动，造成手感严重粘滞。
- **界面极简主义才是最高安全性**：室外阳光下飞手心理极度紧张，繁复的舵量切换、双向微调在移动端不但没有实用价值，反而极易导致误触。将复杂配置沉淀到弹窗中，在未连接实体手柄时自动隐藏手柄油门切换，能最大限度降低人因失误。

### 8.3 安全状态机的“单向锁存”与“分级自稳”哲学
- **低压反弹陷阱与单向锁存（Sticky）**：1S 锂电池内阻较大，大油门机动时电池端电压被大电流压降拉低；一旦飞控收油门试图降落，放电电流骤降导致电压立即回弹到 3.5V 以上。若安全逻辑只写瞬态 `if (vbat < 3.3V)`，飞机会在空中陷入“低压降油门 → 电压回弹恢复大油门 → 再次低压”的往复振荡抽搐（发羊癫疯）。**正解是低压迫降（`LOWBAT_LAND`）必须设计为单向锁存状态**，一经触发，除非飞手主动拨动摇杆上锁归零，否则绝不自动退回正常飞行态；同时送入安全状态机的模拟量必须经过数字低通滤波（`vbat_filtered`），消除 20kHz 电机 PWM 开关毛刺。
- **瞬时阵风倾角与真倒扣的分级救机（E-02）**：单纯写 `tilt > 60° 立即断电` 是机械教条主义——户外一阵强侧风吹过，飞机倾角瞬时达到 62° 但机身姿态完全受控，此时直接切断电机只会让原本能自稳救回的飞机直接自由落体坠毁。**正解是分级保护**：
  - `>110°`（真倒扣）：单拍立即 `FAILSAFE` 断电停机，防止倒地后桨叶刮地烧毁 MOS 管或伤人；
  - `>60°`（大角度失稳）：摇杆指令强制归零，油门压低至悬停推力（40%），内环 PID 爆发出全部差动力矩全力回正机身；设置 45° 滞回退出角与 0.8 秒（320 拍）失控保护计时，超时无法自救才执行切电。
- **失联与切后台的绝对安全底线（E-04）**：手机切后台、来电弹窗、微信消息下拉、手柄蓝牙意外断连，若系统仅回中弹簧轴而不强制归零油门，如果飞机此前正处于 60% 油门推力，飞机将直接定速飞丢。**必须实施组合保护**：强制 `armed = false` + 油门归零 + 连发 3 帧急停帧，任何输入链路异常一律进入最高安全待命态。

### 8.4 测试哲学：向“假绿灯”和“凑参数过关”宣战
- **杜绝 Fake Green Tests**：没有任何断言、只在末尾 `printf("PASS\n")` 并无条件 `return 0` 的测试是工程自欺欺人。所有的测试用例必须内置带非零退出的 `CHECK(cond, msg)` 断言，并在编译阶段开启 `-Wall -Wextra -Werror=return-type`。当测试出现超调、发散或偏差时，**严禁通过盲目修改阈值或迁就测试数据来强行刷绿**，必须追查滤波器冷启动、积分累加边界与时序分频的真实根因。
- **桌面单测与交叉编译完全解耦**：核心算法头文件（LPF、Mahony、PID、混控、安全状态机）必须保持高移植性的纯 C 语言编写（无任何单片机专有库依赖）。这样在没有物理单片机硬件或交叉编译工具链尚未下完的情况下，也能在 PC 宿主机上 50 毫秒内完成全逻辑自动化验收，极大解放了敏捷迭代效率。

### 8.5 交叉编译环境与工程资产管理
- **本地庞大工具链与版本库严格隔离**：PlatformIO 下载的交叉编译器和官方 SDK（通常几百 MB）属于本地机器运行环境，必须放入 `.gitignore`。代码仓库只应当保留轻量纯净的配置文件（如锁定版本号 `espressif32@6.9.0` 的 `platformio.ini`）与业务源代码。
- **开发节奏不被环境安装卡脖子**：由于算法和协议已经在桌面测试矩阵中取得了真绿灯闭环，开发者完全可以先推进代码归档、文档撰写与物料采购，工具链下载完全可以后台异步进行，保持高效稳健的开发心流。
